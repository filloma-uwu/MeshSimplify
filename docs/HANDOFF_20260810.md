## 2. 用户的最终目标和硬约束

这是为 PQSS 碰撞检测生成保守代理 Mesh 的独立 CPU 项目，不是视觉渲染简化器。

- 输出必须严格包围原模型，允许假阳性，不允许假阴性。
- 最大单向误差是用户设置的硬约束。当前默认值为 OBJ 模型单位下的 `100`。
- 误差方向是“简化结果到填洞后参考模型”的最近距离；填洞本身不计入阶段 3 的合并误差。
- 结果输出普通三角形 OBJ，可以直接交给 PQSS。
- 不要求水密、流形或无自相交；除非某个局部封闭表示确实能降低碰撞工作量，否则不要为这些性质增加复杂度。
- 算法在 CPU 上离线运行；构建耗时不是最终目标，但不能发生内存爆炸，单进程上限保持 2 GB。
- 最重要的最终评价指标是碰撞检测中的 BV 测试数和三角形测试数。当前图元数和代理三角形数只是离线阶段可用的工作量代理。
- 不允许按照模型 ID、文件名或坐标写特判。所有模型必须走同一算法。
- 不要用全局凸包/QHull 作为快捷候选。用户要的是局部相邻图元在误差允许时自然合并，而不是直接对整个模型取凸包。
- 合并候选只应是解析曲面/面图元，不应先构造 OBB、圆柱、圆台等立体候选。最终代理是外表面集合。
- 图元内部、完全被遮挡的部分、重复面和重叠面没有碰撞检测价值，应删除或裁剪；但不能误删外壳。
- 每个有意义的算法版本都要提交 Git。

官方简化范围固定为：

`2、3、4、5、12、13、14、15、16、17、18、19、20`

## 3. 当前算法结构

主要实现：`src/primitive_mesh_analyzer.cpp`

算法文档：`docs/PRIMITIVE_ANALYSIS.md`

当前流水线：

1. 预处理源 OBJ，过滤退化三角形。
2. 识别并填洞/空腔，同时删除不再有意义的内壁并补齐开口。
3. 识别解析表面图元。目前主要包括 polygon、disk、annulus、cylindrical band、conical band。
4. 对相邻图元做误差受限的合并；删除内部/遮挡/重复部分，并循环重建候选直到固定点。
5. 将最终图元三角化为 OBJ。
6. 独立执行严格包围审核、误差审核和 OBJ 合法性审核。

查看器应保留并展示四个阶段，支持模型切换、误差重新生成、保持镜头、双击选择图元、下一个图元和其他图元透明度控制。

最近一次关键修复位于提交 `9826701`：覆盖审核不再因为 `source_faces` 责任关系丢失就立即修补，而是先检查源三角形是否已被现有代理曲面或闭体证书从几何上覆盖。只有真正未覆盖的源面才进入精确修补。这使 model18 从 1622 个图元/2571 个三角形降至 404/1009，也改善了 model17。

## 5. 当前首要缺陷：model16 遮挡裁剪回退

上一份基线 `outputs/unified_surface_fix_full_parallel_v2` 中：

- model16：250 个图元、906 个代理三角形。
- 覆盖修补前是 242 个图元、809 个三角形；随后只补了 8 个图元、100 个三角形。
- regularized occlusion 识别 901 个 extrusion，但因旧覆盖审核失败而整体回滚。

当前 `audit_owner_geometry_full_v1` 中：

- model16：377 个图元、1466 个代理三角形。
- 新几何覆盖审核通过，因此 regularized occlusion 没有回滚。
- 该步骤识别 852 个 extrusion，删除 684 个图元，裁剪 774 个图元，输入 2059 个三角形，输出 1054 个三角形。
- 虽然局部裁剪看起来减少了该步骤的三角形，但它制造了大量边界碎片，后续阶段的最终工作量反而增加。

这说明 `clipRegularizedPlanarOcclusion` 当前只关注覆盖正确性和局部结果，没有用最终代理工作量判断该步骤是否值得保留。

## 6. 建议直接执行的下一步

1. 阅读并定位 `clipRegularizedPlanarOcclusion` 的输入、输出和当前 rollback 条件。
2. 增加通用的复杂度接受准则。至少比较裁剪前后实际三角化工作量、图元碎片数和边界环数量；若裁剪没有降低近最终工作量，或碎片增长抵消了收益，就回滚整个 pass。
3. 接受准则不能看模型 ID，也不能只为 model16 设置阈值。先在 model16 验证，再回归 `4、13、14、15、17、18、20`，确保这些当前获益模型不退化。
4. 使用新的干净输出目录重新跑全部 13 个模型，不复用旧 `model.json`。
5. 更新默认 manifest，运行自动审核、C++、Python 和 Playwright 测试。
6. 打开四阶段查看器逐个检查异常图元数、重叠面积和审核修补数高的模型。
7. 提交 Git，并在报告中同时列出新旧图元数、三角形数和误差，不要只报告“审核通过”。

当前最安全的第一版接受条件是：若遮挡裁剪后的实际三角化面数不低于裁剪前，直接回滚；如果面数下降但图元/边界碎片大幅上升，也应回滚。更准确的做法是让该 pass 在临时结果上运行后，执行一次低成本的后续归并估算，再比较预计最终三角形数。
